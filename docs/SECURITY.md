# دليل الأمان والحماية — رُشد

## بصراحة أولاً

لا يوجد نظام في العالم «لا يمكن اختراقه» بنسبة ١٠٠٪، ومن يعدك بذلك لا يقول الحقيقة.
ما بُني في رُشد هو **دفاع متعدد الطبقات**: إذا سقطت طبقة تبقى البيانات محمية بالطبقات الأخرى،
وأي تلاعب يُكتشف. والجزء الباقي من الأمان مسؤولية التشغيل: HTTPS، كلمات مرور قوية، حماية المفتاح
الرئيسي، والتحديث المنتظم — وكلها موضحة في قائمة التشغيل الآمن أدناه.

## ماذا نحمي، ومن ماذا؟

| التهديد | كيف يتصدى له رُشد |
|---|---|
| **سرقة الخادم أو القرص أو نسخة احتياطية** | كل صورة روشتة وكل قراءة وكل نموذج مدرَّب **مشفر بـ AES‑256‑GCM**. المفتاح الرئيسي محفوظ منفصلاً عن البيانات، والنسخ الاحتياطية مشفرة بكلمة مرور. من يسرق البيانات وحدها يحصل على ملفات بلا معنى. |
| **تسريب قاعدة البيانات وحدها** | الصور ليست في قاعدة البيانات أصلاً، والقراءات مشفرة، وكلمات المرور مخزنة بـ **Argon2id**، ورموز الجلسات مخزنة كبصمة (hash) لا يمكن استخدامها. |
| **تخمين كلمات المرور** | سياسة كلمات مرور قوية، **قفل الحساب ١٥ دقيقة بعد ٥ محاولات خاطئة**، حد للمحاولات من كل عنوان IP، رسائل خطأ موحدة لا تكشف أسماء المستخدمين، **تحقق بخطوتين إلزامي للمديرين** ومتاح للجميع، ولا يمكن إعادة استخدام رمز التحقق نفسه. |
| **سرقة الجلسة / XSS / CSRF** | كوكي `HttpOnly` + `Secure` + `SameSite=Strict` + بادئة `__Host-`، رمز CSRF لكل جلسة، فحص `Origin` و`Sec-Fetch-Site`، سياسة **CSP صارمة** (لا سكربتات خارجية ولا inline)، الواجهة لا تكتب بيانات الخادم كـ HTML أبداً، انتهاء الجلسة بعد ٣٠ دقيقة خمول و١٢ ساعة كحد أقصى، وإنهاء كل الجلسات الأخرى عند تغيير كلمة المرور. |
| **ملف Excel مفخخ** | أسماء الأدوية الجديدة يكتبها الصيادلة، فقد يكتب أحدهم «معادلة» بدل اسم دواء. عند تصدير قائمة الأدوية تُعطَّل أي خانة تبدأ كمعادلة، فلا يُنفَّذ شيء عند فتح الملف في Excel. |
| **ملف خبيث متنكّر في صورة** | كل صورة تُفك بالكامل ثم يُعاد بناؤها من البكسلات، فتُحذف بيانات EXIF/GPS وأي محتوى مخفي. حدود للحجم والأبعاد ضد «قنابل الضغط». أرشيفات ZIP لا تُفك على القرص أبداً، ولكل ملف داخلها حد. |
| **موظف يتجاوز صلاحياته** | صلاحيات حسب الدور (مدير / مدرب / صيدلي / متدرب). الصيدلي يرى روشتاته فقط. كل اطلاع على روشتة من غير صاحبها **يُسجَّل**. الإجراءات الحساسة (تصدير البيانات، تدريب نموذج وتفعيله) تتطلب **إعادة إدخال كلمة المرور ورمز 2FA**. |
| **جلسة مدير مسروقة أو كمبيوتر تُرك مفتوحاً** | إدارة الحسابات (إنشاء مستخدم، إعادة تعيين كلمة مرور، تغيير دور، تعطيل حساب، إعادة ضبط 2FA) **تطلب كلمة المرور ورمز 2FA من جديد**، ويبقى التأكيد صالحاً ١٠ دقائق فقط لنفس الجلسة. فمن يجد جلسة مفتوحة لا يستطيع إنشاء حساب سري لنفسه أو الاستيلاء على حساب موظف بدون كلمة المرور والهاتف — إلا خلال تلك الدقائق العشر، لذلك أغلق الجلسة عند الابتعاد عن الجهاز. |
| **سرقة «النموذج» الذي دربته** | أوزان النموذج المدرَّب تُحفظ **مشفرة** ولا تُفك إلا في الذاكرة لحظة الاستخدام، بصيغة safetensors التي لا تنفذ أي كود. لا يُحمَّل أي نموذج بخاصية تنفيذ كود خارجي. الحد اليومي للقراءات يمنع «استنزاف» النموذج آلياً. |
| **التلاعب بسجل الأمان لإخفاء أثر** | كل سطر في السجل موقَّع بـ HMAC ومربوط بالسطر الذي قبله، مع حفظ «رأس السلسلة» في ملف منفصل. تعديل أو حذف أو إعادة ترتيب أي سطر — حتى من قاعدة البيانات مباشرة — **يُكتشف** بزر «فحص سلامة السجل». |
| **التنصت على الشبكة** | HTTPS إلزامي عبر Caddy مع HSTS، والتطبيق نفسه غير مكشوف للشبكة، وفحص اسم النطاق (Host). |
| **استهلاك مفرط أو تكلفة غير متوقعة** | حد لحجم الطلبات، حد يومي للقراءات لكل مستخدم، وحد شهري لتكلفة القراءة السحابية. |

## المفتاح الرئيسي — أهم ما تحميه

- مفتاح عشوائي بطول ٢٥٦ بت يُنشأ عند أول تشغيل (`secrets/master.key` أو وحدة `rushd-secrets` في Docker) بصلاحيات `600`.
- تُشتق منه مفاتيح مستقلة (HKDF) لكل غرض: الصور، القراءات، كشف التكرار، سلسلة السجل، الرموز المؤقتة.
- **لا يمكن رؤيته أو تعديله من واجهة البرنامج**، ويظهر في الإعدادات «بصمته» فقط.
- **احتفظ بنسخة منه خارج الخادم** (فلاشة مشفرة في خزنة). بدونه لا يمكن استرجاع أي بيانات، ومعه وحده — بدون البيانات — لا قيمة له.
- تدوير المفتاح (مثلاً عند الاشتباه في تسريبه): أوقف الخادم، خذ نسخة احتياطية، ثم:
  ```bash
  python -m rushd rotate-key
  ```
  يعيد تشفير كل شيء بمفتاح جديد، ويحتفظ بالملفات القديمة بامتداد `.before-rotation-…` حتى تتأكد ثم تحذفها.

## قائمة التشغيل الآمن

- [ ] التشغيل عبر **HTTPS فقط** (`docker compose` مع Caddy). لا تستخدم `RUSHD_COOKIE_SECURE=false` إلا للتجربة على نفس الجهاز.
- [ ] نسخة من **المفتاح الرئيسي** في مكان آمن غير متصل بالإنترنت.
- [ ] **التحقق بخطوتين** لكل المديرين والمدربين (ويُفضَّل للجميع).
- [ ] حساب مستقل لكل شخص — **لا حسابات مشتركة** — وتعطيل حساب أي موظف يترك العمل فوراً.
- [ ] **نسخة احتياطية مشفرة يومياً** خارج الخادم: `python -m rushd backup <ملف>`، وجرّب الاستعادة دورياً.
- [ ] تحديث الخادم والحاويات شهرياً (`docker compose pull && docker compose up -d --build`).
- [ ] **فحص سلامة سجل الأمان** أسبوعياً، ومراجعة محاولات الدخول الفاشلة.
- [ ] ضبط **حد الميزانية الشهرية** والحد اليومي للقراءات من الإعدادات.
- [ ] جدار ناري لا يفتح إلا المنفذين 80 و443.
- [ ] الخادم في مكان مغلق، ويفضل تشفير قرصه بالكامل (LUKS / BitLocker) كطبقة إضافية.
- [ ] مفتاح Claude API خاص بهذا الخادم فقط، مع حد إنفاق في حساب Anthropic.

## عند الاشتباه في اختراق

1. افصل الخادم عن الإنترنت أو أوقف Caddy: `docker compose stop caddy`.
2. من «المستخدمون»: أنهِ جلسات الجميع وأعد تعيين كلمات المرور.
3. افحص سلامة سجل الأمان وراجع الأحداث (من الواجهة أو `python -m rushd verify-audit`).
4. غيّر مفتاح Claude API من console.anthropic.com، ثم دوّر المفتاح الرئيسي.
5. استعد من آخر نسخة احتياطية سليمة إن لزم: `python -m rushd restore <ملف> <مجلد فارغ>`.

## أوامر الطوارئ

| الأمر | الاستخدام |
|---|---|
| `python -m rushd reset-password admin --reset-2fa` | استعادة الدخول لمدير فقد هاتفه أو كلمة مروره (يحتاج صلاحية على الخادم). |
| `python -m rushd verify-audit` | فحص سلامة سجل الأمان. |
| `python -m rushd backup <ملف>` / `restore <ملف> <مجلد>` | نسخ احتياطي مشفر واستعادته. |
| `python -m rushd rotate-key` | تدوير المفتاح الرئيسي. |

(داخل Docker: `docker compose exec rushd python -m rushd …`)

## حدود معروفة — بصراحة

- **تطبيق الأندرويد** يمنع لقطات الشاشة وتسجيلها، ولا يتصل إلا بعنوان رُشد الذي تحدده (أي رابط آخر يفتح خارج التطبيق)، ويرفض الاتصال غير المشفر (http) إلا داخل شبكة الصيدلية المحلية. صور الروشتات التي تلتقطها الكاميرا تُحذف من الموبايل خلال ساعة.
- **نسخة الكمبيوتر في وضع «مشاركة الموبايلات»** تعمل بـ HTTP داخل شبكة الصيدلية: البيانات مشفرة على القرص، لكن الاتصال نفسه داخل الواي فاي غير مشفر. استخدمها على واي فاي محمي بكلمة مرور فقط، ولتشغيل الفروع من أي مكان استخدم الخادم بـ HTTPS. (الوضع العادي `Start-Rushd` لا يقبل اتصالاً إلا من نفس الكمبيوتر.)
- من يملك صلاحية **root** على الخادم أثناء تشغيله يستطيع نظرياً الوصول للمفتاح في الذاكرة؛ لذلك حماية الخادم نفسه جزء من الأمان.
- في **الوضع السحابي** تُرسل صورة الروشتة (بعد إخفاء ما تختاره) مشفرة عبر TLS إلى Anthropic للقراءة. للخصوصية القصوى استخدم وضع «محلي بالكامل» بعد تدريب نموذجك.
- الحذف الآمن على أقراص SSD «أفضل جهد»، لكن البيانات المحذوفة مشفرة أصلاً.
- الحد من المعدل يعمل داخل عملية واحدة (مناسب لخادم واحد)؛ للتوزيع على عدة خوادم يلزم Redis وقاعدة PostgreSQL.
